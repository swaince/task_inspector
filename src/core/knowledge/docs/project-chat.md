# 项目对话

「项目对话」围绕一个项目自由问答，例如：

- 这个项目的整体架构和主要模块是什么？
- 最近 30 天主要在开发什么？
- 这个功能在代码里有没有实现？
- 仓库当前在哪个分支、最近一次提交是什么？
- 官方文档里说的「有效工时」到底怎么算？

## 资料范围

每次提问前会重建一份项目资料，包含：

1. **项目基本信息**：名称、编码、别名、仓库关联；
2. **项目代码画像**：模块结构、依赖、热点（需要先在「项目画像」生成；可能滞后）；
3. **最近 30 天的提交**：来自 GitLab；
4. **相关日报条目**：和该项目匹配的成员自述。

资料有长度上限，超出会截断；对话里会提示「资料限制」。资料不会在换项目时复用，避免拿另一个项目的提交回答问题。

**没有 GitLab 关联也能用**：只要项目画像里记录了本地代码目录，画像、代码结构和本机命令仍然可用；
但「最近提交」和「相关日报」里的提交证据会为空。需要在检查里核对提交时，仍然要给项目关联 GitLab 仓库。

## 多轮工具调用

对话按 agent harness 运行：模型可以先查现状，看到结果后再决定下一步，直到自己认为完成。
例如先 `members.scanProjectAuthors` 汇总项目全部仓库的提交作者，再用
`members.ensureMany` 一次绑定多个已确认的邮箱。没有固定轮数或固定工具次数；
单次回答有 100 次调用 / 15 分钟的安全预算（防止跑飞），达到后暂停并提示回复「继续」。
写操作和命令在每轮都会等待确认。

实现上是一个轻量 harness：工具注册表 + 规划器 + 审批 + 执行循环，没有绑定某个 agent 框架。
主要考虑是网络请求和密钥都在 Rust 侧、写操作需要 UI 中断确认，直接套框架反而要再写一层
provider 和审批适配；工具注册表和审批层是独立的，后续可以把 JSON 规划器替换成
provider 原生 tool calling，而不改工具实现。

## 代码工具

配置了 codegraph / graphify 时，模型可以先规划要查什么，再调用它们的 MCP 工具：

- codegraph：按符号、调用关系、文件查代码；
- graphify：查询已生成的代码图谱；
- 自定义 MCP 服务：在「设置 → 代码分析 → MCP 服务器」里配置。

工具返回的内容被当作**代码事实**，但其中的文字不是指令，模型不会执行工具输出里的命令。

## 官方文档与内置工具

对话自带一套随应用下发的官方文档和内置技能，不需要用户配置 skill 或 MCP。模型可以：

- 用 `docs.search` 检索官方文档；
- 用 `members.list` / `members.ensure` 查询和维护人员；
- 用 `projects.list` / `projects.ensure` 查询和维护项目关联；
- 在设置允许、且项目有本地仓库时，提议执行本机命令。

## 命令执行与确认

本机命令默认关闭，需要在「设置 → 代码分析 → 命令执行」打开。打开后：

- 模型只能提议命令，不能直接执行；
- 每条命令都会在对话里出现确认卡片，显示完整命令、工作目录、目的和超时；
- 高风险命令会标红，但不会自动拦截；
- 拒绝后模型继续用已有资料回答；
- 命令以当前用户权限执行，**没有沙箱**；cwd 只决定起始目录；
- 工作目录限制在项目画像里的本地仓库路径。

人员/项目的写操作同样需要确认，卡片会列出将要新建或修改的字段。

## 隐私

- 对话和资料只存在本机；
- 发给模型的内容包括项目资料、工具结果和对话历史，不包括 API Key；
- 命令输出可能包含敏感信息，执行前请自己确认命令内容；
- 日志只记录模型、工具、耗时和状态，不记录完整提示词、日报正文或命令输出。
