# 项目与 GitLab 关联

「项目」页维护的是**日报里的项目**和**GitLab 仓库**之间的对应关系。检查时，日报条目先按项目名/别名匹配到本地项目，再用项目的 GitLab 关联去拉提交。

## 项目字段

- **名称**：和日报里的项目名对应；
- **编码**：日报系统里的项目编码，用于精确匹配；
- **别名**：同一项目在日报里的其它写法；
- **匹配模式**：精确、包含、正则；默认精确，别名多时可以用包含；
- **开发模式**：人工开发 / AI 辅助 / AI 开发，影响有效工时的代码量修正；
- **关注 / 启用**：只有关注且启用的项目会进入检查范围。

## GitLab 关联

一条关联有两种：

| 类型 | 含义 |
|---|---|
| 仓库（repo） | 直接关联一个仓库，路径形如 `group/subgroup/repo` |
| 组（group） | 关联一个 GitLab 组，包含所有子组和仓库 |

「解析关联仓库」会调用 GitLab API，把关联展开成仓库列表，并记录解析状态：

- `synced`：解析成功；
- `unsynced`：还没解析；
- `missing`：之前能解析，现在找不到了；
- `error`：权限、路径或网络错误。

组关联适合整个产品/子系统都在一个组下的情况；仓库关联适合一个项目跨多个不相关仓库的情况。

## 在界面上添加关联

项目编辑表单里的「搜索并添加仓库/组」会打开 GitLab 选择器：

- **默认用项目编码作为关键词**；没有编码时用项目名称；
- **一个输入同时模糊匹配仓库名、组名和完整路径**；结果里用徽标区分仓库和组；
- 只会显示当前 Token 能看到的仓库和组；选中即加入关联，已添加的会标记出来；
- 某个接口不可用（例如旧版本 GitLab 没有组搜索权限）时，另一侧的结果仍然保留；
- 找不到时可以在选择器底部手动填写仓库或组的完整路径。

添加后点「解析关联仓库」展开成具体仓库；解析结果会写进项目配置。

## 本地代码目录

项目画像需要本地代码。应用会按「设置 → 代码分析 → 代码目录」下的 `<namespace>/<repo>` 找已有 checkout；打开「自动克隆」时，找不到会浅克隆到该目录。项目画像里记录的 `repos[].localPath` 也是项目对话执行本机命令时唯一允许的工作目录。

克隆会保留 **origin 的全部远程分支引用和标签**，但可以按设置做浅克隆（限制历史深度）。已有 checkout 不会覆盖工作区，只会补拉远程引用。

## 分支与画像

- 克隆后保留 origin 的全部远程分支和标签；画像会先比较各分支最近提交时间；
- **优先分析最近提交的分支**，没有最新信息时退回默认分支；
- 如果目标分支不是当前工作区分支，会在临时 git worktree 里分析目标分支，不改动用户工作区；
- 如果临时工作树创建失败，画像会明确报错，不会偷偷分析当前分支；
- 画像会记录每个仓库的默认分支、最近提交分支、本地当前分支、实际分析分支和分支引用数量；
- 画像还会统计近段时间（默认 90 天，可在设置里调）**每个有提交的分支各自在做什么**：提交数、最近提交时间和几条提交标题；
- 项目对话可以用 `projects.branches` 先确认各仓库分支和各分支工作，再回答代码/提交类问题。

**分析不片面**：逐日检查、项目活动、人员活动、项目画像和项目对话都按「时间范围内有提交的分支」收集数据，而不是只看默认分支。默认分支始终保留，其余分支只要窗口内有提交就参与；每条提交会记录它出现在哪些分支。分支数量过多时按最近提交排序取前若干条，并提示未扫描的分支数。

## 项目画像

「项目画像」会扫描本地仓库，生成：

- 文件数、模块划分、模块间依赖和循环依赖；
- 近期改动热点；
- 模块摘要和一份代码分析报告。

画像**不强制要求先解析 GitLab 仓库**：在画像页的「扫描范围」里可以直接添加本地代码目录，
应用会扫描这些目录并生成画像；目录会记在画像里，下次生成自动回填。没有 GitLab 关联时，
提交记录仍然为空，所以「执行检查」不能仅靠本地目录完成。

画像可能滞后于代码；对话引用画像时会注明生成时间。没有画像时，代码类问题只能依据仓库信息和提交记录回答。

## 项目对话里的维护

项目对话可以用 `projects.ensure` 维护关联：

- 输入完整的 GitLab URL、`group/subgroup` 或 `group/repo`；
- 应用会先校验 GitLab 中是否存在，查不到不写库；
- 已存在相同关联时忽略；
- 新增关联后会重新解析仓库；
- **不会在 GitLab 侧创建组、仓库或用户**，也不会删除项目或关联。
