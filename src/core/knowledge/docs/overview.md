# 应用概览

「研发工作核查」是一个桌面工具，用来核对**日报里申报的工作内容**和**当天在 GitLab 上的实际代码提交**是否一致。它不替代日报系统，也不做考勤，只回答三个问题：

1. 日报里写的每件事，能不能在当天的提交里找到证据；
2. 有没有「提交了代码，但日报没写」的漏报；
3. 一段时间内，各项目、各人员的投入和产出大致是什么样。

## 主要页面

| 页面 | 用途 |
|---|---|
| 概览 | 最近一次检查的汇总、需要关注的人、全部结果入口 |
| 执行检查 | 选日期区间，按关注成员 × 工作日批量检查 |
| 检查历史 | 按批次、日期回看结果，点进单条结果 |
| 应用助手 | 查官方文档、问功能和数据口径，在确认后维护人员与项目关联 |
| 项目活动 | 一个项目在一段时间里的提交、日报、有效工时 |
| 人员活动 | 一个人在一段时间里跨项目的产出与申报构成 |
| 项目 | 维护项目、别名、GitLab 仓库/组关联、项目画像 |
| 项目画像 | 扫描本地代码，生成模块结构和代码分析报告 |
| 项目对话 | 围绕单个项目自由提问，可调用代码工具和本机命令 |
| 人员 | 维护日报 ID、邮箱、GitLab 用户名、关注/启用 |
| 设置 | GitLab、日报系统、模型、判定规则、代码分析、工作日历、数据 |

## 推荐使用顺序

1. 在「设置」配置 GitLab 和日报系统，填模型；
2. 在「人员」维护成员和 GitLab 身份，把要检查的人设为关注；
3. 在「项目」维护关注项目和 GitLab 仓库/组关联；
4. 需要代码级细节时，在「项目画像」生成画像；
5. 在「执行检查」选区间运行，之后到「概览」「检查历史」看结果；
6. 需要跨项目看投入时用「项目活动」「人员活动」；
7. 需要问「这个功能怎么用」或维护人员/项目时，用「应用助手」；
8. 需要追问某个项目的代码细节时用「项目对话」，它可以查官方文档、维护人员/项目、执行确认后的本机命令。

## 关键边界

- 检查只依据 GitLab 提交和日报，不读取聊天记录、工时系统或本地未提交的代码；
- 判定是辅助，不是绩效结论；「无法核对」不等于「没干活」；
- 有效工时是由提交和 MR/评审/Issue 等活动证据推算的区间；会议、答疑等没有系统痕迹的工作不强行计入；
- 项目对话里的写操作和命令都需要人工确认。
