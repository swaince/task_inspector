# 对话内置工具

项目对话自带一组内置工具，不需要用户配置 skill 或 MCP。它们和外部 MCP 工具共用同一个规划器和执行循环。

对话支持**多轮工具调用**：模型可以先查询，看到结果后再决定下一步，直到它认为信息足够。
没有固定轮数或固定工具次数；只有一个防止跑飞的安全预算（单次回答 100 次调用 / 15 分钟），
达到后会暂停并提示你回复「继续」。写操作在真正执行前都会等待确认。
确认卡片支持「本次回答内全部允许」：点一次后，这次回答后续的同类写操作不再逐条弹卡片；
新提问会恢复逐条确认，不会永久跳过授权。

## 文档检索（只读）

`docs.search`

- 输入：`query`（自然语言或关键词）或 `docId`；
- 输出：命中的文档、章节和片段；`docId` 模式返回整篇；
- 用途：回答「这个功能怎么用」「这个分数怎么算」「为什么报错」；
- 官方文档随应用版本下发，不需要用户维护。

## 人员（只读 + 写）

`members.list`（只读）

- 按姓名、日报 ID、邮箱、GitLab 用户名搜索；
- 返回关注/启用状态和账号信息。

`members.scanProjectAuthors`（只读）

- 输入项目名称/编码（项目对话里可省略）和回看天数；
- 扫描该项目**全部已解析的 GitLab 仓库**，汇总提交邮箱、提交者姓名、提交数和涉及仓库；
- 和现有成员按邮箱/姓名/GitLab 用户名匹配，输出「已绑定 / 建议绑定 / 未匹配 / 冲突」；
- 问「这个项目有几个开发、账号邮箱是什么」时优先用它，不要用 shell 只查一个仓库。

`members.ensure`（写，需要确认）

- 示例：「张三关联账号 zhangsan@126.com」；
- 匹配顺序：日报 ID → 工号 → 唯一姓名；
- 找到时只补空字段，不覆盖已有值；
- 邮箱/用户名已属于别人时返回冲突，不写库；
- 找不到时新建成员，默认关注、启用；
- 不删除成员，不合并账号。

`members.ensureMany`（写，整批一次确认）

- 输入多个成员及其邮箱/用户名；
- 每一项按 `ensure` 的规则匹配；任何一项冲突则整批不写；
- 适合「把已确认的邮箱绑定到相关人员」这种批量配置；
- 用户只看到一张确认卡片，里面列出每个成员的变更。

`members.bindProjectAuthors`（写，扫描 + 绑定准备一次完成）

- 输入项目名称/编码（项目对话里可省略）和回看天数；
- 扫描项目全部 GitLab 仓库，按姓名/邮箱匹配现有成员，为匹配上的成员补齐邮箱；
- 只准备匹配上的成员，不会给未匹配的提交身份自动建人；
- 扫描和绑定准备一次完成，只弹一张确认卡片；
- 用户说「采纳 / 绑定吧 / 继续」时用它，不要只查询后声称等待确认。

## 项目（只读 + 写）

`projects.list`（只读）

- 按名称、编码、别名搜索；
- 返回 GitLab 关联、解析出的仓库、关注/启用状态。

`projects.branches`（只读）

- 查看项目每个仓库的最近提交分支和提交时间、默认分支、本地当前分支、画像分析分支和远端分支引用；
- 列出近段时间每个有提交的分支在做什么（提交数、最近时间、近期标题）；
- 本地代码目录存在时读取实时分支，否则用画像/项目关联里的默认分支；
- 回答代码结构、提交、画像或「在哪个分支」「哪个分支做了什么」问题前先用它；画像优先分析最近提交的分支，但分支工作要全量看待。

`projects.ensure`（写，需要确认）

- 示例：「项目 X 的 GitLab 组是 group/sub」或「项目的 Git 地址是 https://…/group/repo.git」；
- 先在本应用里按编码/名称/别名找项目，找不到才新建；
- GitLab 关联先校验存在性：仓库用项目接口，组用组接口；
- 已存在相同关联时忽略；
- 新增关联后重新解析仓库；
- GitLab 查不到时明确报错、不写库；
- **不会在 GitLab 侧创建组、仓库或用户**；不删除项目或关联。

## 命令执行（写，需要确认）

`shell.run`

- 前提：设置里打开「命令执行」、桌面端、项目有本地仓库；
- 输入：`command`、`cwd`、`reason`、可选超时；
- cwd 必须是项目本地仓库目录；
- 每条命令都弹出确认卡片，显示完整命令、目录、目的、超时；
- 高风险模式标红但不拦截；
- 输出有上限，超时会杀进程树；
- 没有沙箱，确认是唯一安全边界。

## 使用纪律

- 功能/设置问题先查文档，不凭印象回答；
- 人员/项目写操作使用 ensure，天然幂等；
- 命令只作为兜底，优先只读；
- 被拒绝的操作不会执行，模型不能声称已经完成；
- 文档没有覆盖的内容直接说「官方文档没有这项说明」。
