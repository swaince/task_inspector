# 项目活动与人员活动

「项目活动」「人员活动」的视角是「一个项目/一个人 × 一段时间」，由代码侧驱动，再用日报做对照。

## 项目活动

选一个项目 + 一段时间，看：

- 谁在该项目提交了什么、改了多少行；
- 谁在日报里报了这个项目、报了多少工时、写了什么；
- 哪些工作日有提交但日报没写，或报了工时但当天没提交；
- 报告页的每日趋势图和人员投入图。

**分支范围**：统计覆盖区间内**所有有提交的分支**，默认分支始终保留；每条提交带分支标签，报告里有单独的「分支工作」一节，写明哪个分支干了什么。只看默认分支会漏掉功能分支上的工作。

**仓库范围**：每次分析前会重新解析项目的 GitLab 关联；关联的是组时，组里新增的仓库会自动纳入本次扫描。解析部分失败时保留上一次的仓库清单并提示，不会因为一次网络问题把仓库清空。

**日报范围**：分析只读本地已同步的日志，不会在每次打开/分析时请求日志中心；需要最新内容时先到「日志」页做增量或全量同步，或在单人详情里强制更新。

分组方式：

| 视图 | 用途 |
|---|---|
| 明细 | 日期 × 人员，逐条看提交和日报 |
| 按天 | 每天的提交数、参与人、代码量、申报工时、有效工时 |
| 按人 | 每个人的提交、活跃天数、代码量、申报工时、未申报天数 |
| 分析报告 | 模型基于以上数据生成的结构化报告 |

## 人员活动

选一个人 + 一段时间，看这个人在各项目上的产出和申报构成：

- 项目占比：日报申报占比 vs 代码估算占比；
- 每日趋势、活跃时段、提交集中度；
- 有提交未申报、有申报无提交的天数；
- 分析报告。

## 有效工时

有效工时是**由可观测证据推算的区间**，不是考勤：

- 下限只认提交：按提交会话估算，会话有首尾缓冲，再乘保守系数；
- 上限叠加 MR / 评审 / Issue 活动、当天首末活动的在岗跨度，以及可选的模型任务估算；
- 同一份工作会在多种证据里重复出现，所以取最宽的一路，不相加；
- 按项目的开发模式（人工 / AI 辅助 / AI 开发）修正代码量；
- 输出是区间，不是精确小时数；
- 会议、答疑、调研等没有系统痕迹的工作不强行计入。

工作饱和度 = 有效工时中值 / 标准工时，只适合和本人其它日子比较，不适合跨人排名。

参数在「设置 → 分析 → 工时估算口径」里标定；「读取 MR / 评审 / Issue 活动」和「模型按任务估算」可以分别关闭。

## 申报对照（代码证据）

项目活动和人员活动都有「申报对照」页签，用来回答「日报说做了什么，代码实际改了什么」：

- 先确保本地仓库有 codegraph 索引（有索引则增量 sync，没有则 init）；
- 取提交的改动文件，用 codegraph 检索相关符号和源码；
- 把申报内容、提交和代码证据一起交给模型，逐条给出「一致 / 部分一致 / 无代码证据 / 无法核对」及依据；
- 没有代码痕迹的会议、评审等标为「无法核对」，不直接判成没工作。

这个页签按需触发，不会在每次扫描时自动调用模型。索引建立失败时仍会给出提交和文件层面的对照，并明确提示缺少符号级证据。

## 分析历史

项目活动和人员活动都会保存每次分析的结果。日志同步发现某几天有新增、修改或删除时，区间覆盖这些日期的分析记录会被标记为「日志已更新」：

- 记录上会显示黄色标记和变更原因；
- 点「重新分析」会用同一对象和区间重跑一次，完成后标记自动清除；
- 不自动后台重跑，避免同时给日志中心、GitLab 和模型造成压力。

历史页还支持按项目、人员、月份等维度汇总统计。

## 时间窗

提交按「前一天 20:00 到次日 08:00」归到日期，和采集规则用的是同一套时间窗。相邻日期窗口重叠时，提交只归给最早命中的那天。周末和节假日是否算缺报，由工作日历决定。

## 日报核对窗口

在「设置 → 采集规则」里可以配置日报核对的前后滑动窗口（工作日，默认 2 天）。当天没提交、过几天才提交很常见，所以日报会按窗口核对，而不是只看当天：

- 窗口会跨过周末和节假日继续取工作日：周三 → 周一到周五；周四 → 周二到周五；周五 → 周三到本周五，再包含下周一、周二；
- 但窗口不会跨出日报所在的**自然月**：月底最后一天只有前面两个工作日加当天，共 3 天；
- 窗口以**日报日期**为中心；周末加班写了日报，日报日期本身仍在窗口内。分析页会显示每个日报的检查窗口和窗口内提交数，报告也按窗口判断「有申报无提交」。
