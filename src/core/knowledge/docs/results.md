# 检查结果与判定

每条「人 × 天」结果包含：日报条目、每条条目的判定、当天被引用的提交、未被引用的提交、以及一个加权符合度。

## 判定等级

| 判定 | 含义 |
|---|---|
| 一致（matched） | 提交内容明确支撑日报描述 |
| 部分一致（partial） | 方向一致但明显不完整，例如写了「重构 + 补测试」，实际只有重构 |
| 不一致（mismatched） | 有该项目的提交，但内容和描述对不上 |
| 无提交（no-commit） | 该项目当天没有提交；会议、评审、调研、答疑等非编码工作也会落在这里 |
| 无法核对（unverified） | 材料不足，例如没有仓库关联、GitLab 没权限、提交为空 |

## 符合度

符合度是**按日报工时加权的 0–100 分**，只统计「有可核对内容」的条目：

- 一致 = 100；
- 部分一致 = 60（具体权重以判定规则为准）；
- 不一致 = 0；
- 无提交、无法核对 = 不计入分母。

因此，一个人当天如果全是会议和评审，符合度会显示「—」，而不是 0。不要把「—」读成「不合格」。

## 覆盖率与未引用提交

- **未被引用提交**：当天属于该成员、但没有被任何日报条目引用到的提交。项目本身在日报里提到过、只是证据没引到，通常只说明描述不够具体，不等于是整个项目漏报。
- **覆盖率**：有提交、有日报、能互相印证的比例。覆盖率低通常意味着身份没配好、仓库没关联，或者日报写得太笼统。

## 怎么读结果

1. 先看「无法核对」是不是配置问题（人员身份、项目关联、GitLab 权限）；
2. 再看「不一致」的条目，点开提交详情，对照日报原文；
3. 最后看「未被引用提交」，判断是描述遗漏还是另一个项目的工作；
4. 单日结果适合判断「这天说得清吗」，跨天趋势适合看项目或人员的投入结构，两者不要混用。
