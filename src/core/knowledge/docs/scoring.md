# 工时与得分口径

应用里出现三类「工时/分数」，含义完全不同，不要混着读。

## 1. 日报申报工时

来自日报系统的 `workDayPercent` 或工时字段。它表示**申报**，不是实际产出：

- 一天多个项目时，各项目的申报工时相加；
- 申报 8h 不代表写了 8h 代码，也可能是会议、评审、答疑；
- 检查的加权分母用的是申报工时。

## 2. 代码估算有效工时

从提交反推的区间，只统计代码产出：

- 输入：提交时间分布、活跃时段、增删行数、文件类型；
- 按项目开发模式修正：人工开发 / AI 辅助 / AI 开发；
- 输出 `low–high` 区间，不是精确值；
- 不含会议、评审、调研、答疑；
- 同一天多项目时按相对占比分配。

工作饱和度 = 有效工时中值 / 8h。它只适合和本人其它日子比较，**不适合跨人排名**，也不适合当考勤。

## 3. 符合度（0–100）

检查结果里的加权分数，按日报工时加权：

- 一致 = 100；
- 部分一致 = 60（以判定规则里的权重为准）；
- 不一致 = 0；
- 无提交、无法核对 = 不进分母。

所以「100%」只表示**有可核对内容的条目全部一致**，不表示当天产出 8h，也不表示日报写得完整。如果所有条目都无法核对，分数显示「—」。

## 覆盖率

覆盖率描述「有提交、有日报、能互相印证」的比例，用来判断结论的可靠程度，不直接参与得分。

- 覆盖率低：先查人员身份、项目关联、GitLab 权限；
- 覆盖率正常但符合度低：再逐条看判定理由；
- 未引用提交多：可能是日报描述太笼统，也可能是另一个项目的工作。

## 常见误读

| 现象 | 不代表 |
|---|---|
| 100% | 日报完整、产出等于申报工时 |
| 0 分 | 员工没干活；先看分母是否为 0 |
| 「—」 | 不合格；通常是没有可核对内容 |
| 有效工时低于申报工时 | 一定在摸鱼；非编码工作本来就不计入 |
| 未引用提交多 | 整个项目漏报；可能只是证据没引用到 |
