# 常见问题排查

## GitLab

| 现象 | 常见原因 | 处理 |
|---|---|---|
| 401 | Token 无效或过期 | 重新生成 Token，至少 `read_api` |
| 403 | 权限不足 | 确认 Token 有 `read_api`，且能访问目标组/仓库 |
| 404 | 路径错误或没有访问权限 | 用浏览器打开仓库路径确认；检查组路径和分支 |
| 429 | 触发限流 | 降低并发、缩小日期区间、稍后重试 |
| 仓库解析为空 | 组下没有可见仓库，或分支名不对 | 检查组的可见性、Token 成员身份、默认分支 |

## 日报

- **区间内日报为空**：确认来源是「接口」还是「CSV」；接口模式下先点「拉取这一天的日报试试」；日报通常当天晚上才上报，白天查今天本来就是空的。
- **成员匹配不到**：优先补日报 ID；姓名匹配遇到同名会跳过。
- **项目匹配不到**：补项目编码或别名；检查匹配模式（精确/包含/正则）。
- **工时不对**：确认字段映射里的工时字段是 `workDayPercent` 还是小时数。

## 检查结果

- **全是「无法核对」**：GitLab 未配置、人员没有 GitLab 身份、项目没有关联仓库，三者至少中一个。
- **分数显示「—」**：当天没有可核对内容，不是 0 分。
- **未引用提交很多**：日报描述太笼统，或提交属于另一个项目；不一定是漏报。
- **某天失败**：看页面顶部的失败列表，通常是模型超时、GitLab 限流或数据格式异常。

## 代码工具

- **MCP 连接失败**：确认命令能在终端直接运行；codegraph 用 `codegraph serve --mcp`，graphify 需要先有 `graphify-out/graph.json`；
- **工具列表为空**：服务启动失败或没有工具；对话会退化为只用项目资料回答；
- **工具调用超时**：索引太大或服务卡住；缩小问题范围，或检查服务日志。

## 模型

- **模型没有返回内容**：确认模型名、接口地址、Key；流式接口是否被网关缓冲；
- **超时**：默认 120 秒；长回答或大资料可能超过，缩小资料范围或调大超时；
- **JSON 解析失败**：判定和规划环节要求 JSON，部分模型会加解释文字；应用会尝试截取，仍失败时该条判定会退回粗略规则。
- **回答里出现 `<||DSML||invoke ...>`**：这是模型把内部工具调用语法写进了正文。应用会先尝试把它当成工具计划执行；如果最终回答里仍然出现，会从正文中拦截，并在整段都是工具调用时提示重试。换一个更稳定的模型或降低温度通常能避免。

## 命令执行

- **看不到命令工具**：设置里没打开、当前是浏览器预览、或项目没有本地仓库路径；
- **命令被拒绝**：工作目录不在项目仓库列表里，或用户点了拒绝；
- **中文乱码**：Windows 下应用会把 PowerShell 输出统一成 UTF-8；第三方工具直接写非 UTF-8 字节时仍可能出现替换字符；
- **命令超时/取消后进程还在**：进程树清理是尽力而为，脱离进程组的孙进程可能存活，需要手动结束。

## 数据

- **历史突然空了**：检查数据保留天数；清空操作不可恢复；
- **换电脑后配置没了**：配置存在本机 SQLite，不会自动同步；
- **数据库文件很大**：清理检查历史、日报缓存或项目画像缓存。
