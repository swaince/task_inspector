# 人员与账号关联

「人员」页维护的是**日报系统里的人**和**GitLab 提交身份**之间的对应关系。检查能不能把提交归到人头上，几乎完全取决于这里的配置。

## 字段

| 字段 | 用途 |
|---|---|
| 姓名 | 显示名，也是同名匹配的依据 |
| 日报 ID（reportMemberId） | 和日报系统对接时最可靠的匹配键 |
| 工号（employeeNo） | 对接日报系统 / LDAP 时的辅助键 |
| 团队、角色 | 展示用，不参与匹配 |
| GitLab 用户名 | 匹配提交作者的用户名，可填多个 |
| GitLab 用户 ID | 备用数字 ID |
| 邮箱 | 匹配提交作者邮箱，可填多个 |
| 关注 | 决定是否进入检查范围和默认筛选 |
| 启用 | 停用后完全不参与检查 |

## 匹配规则

检查时按「GitLab 用户名 + 邮箱」识别提交作者。一个人可以填多个用户名和邮箱，覆盖公司邮箱、个人邮箱、历史账号等情况。

日报侧优先用 `reportMemberId` 匹配；没有时退回姓名。**同名多人的情况会跳过姓名匹配**，需要补日报 ID。

## 账号冲突

- 同一个邮箱或 GitLab 用户名出现在多个成员上，会在表单里标出冲突；
- 冲突不会自动合并，需要人工确认哪一个是正确的；
- 「未绑定」筛选项列出既没有用户名也没有邮箱的成员，这些人的提交无法归属。

## 同步与导入

- **从日报系统带入**：按日报 ID → 工号 → 唯一姓名匹配，只补空字段，不覆盖已有人工修改；
- **从 GitLab 查找邮箱**：可以用邮箱反查 GitLab 用户，补用户名；
- 批量导入和同步都会给出 created / linked / updated / unchanged / conflicts 统计，冲突会逐条列出。

## 项目对话里的维护

项目对话可以用 `members.ensure` 和 `members.ensureMany`：

- 例如「张三关联账号 zhangsan@126.com」；
- 已有张三时只补邮箱，不覆盖已有字段；
- 邮箱已属于别人时返回冲突，不写库；
- 新建成员默认关注、启用；
- 不会删除成员，也不会自动合并两个已有成员。

要回答「这个项目有哪些开发、对应哪些 GitLab 邮箱」时，先用
`members.scanProjectAuthors`：它会扫描项目**全部已解析仓库**（不是只看一个），
把提交邮箱、提交者姓名、提交数和现有成员匹配，给出「已绑定 / 建议绑定 / 未匹配」。
确认映射后，用 `members.ensureMany` 一次补齐多个成员；整批只弹一次确认卡片，
任何一项冲突都会让整批不写。也可以直接用 `members.bindProjectAuthors`：
它会重新扫描全部仓库、匹配现有成员并准备绑定，扫描和绑定准备一次完成，
同样只弹一张确认卡片。
